# Отримання історії круток для PS5

> Історична нотатка першого етапу дослідження. Після описаних нижче перевірок
> реалізовано браузерне розширення та ручний імпорт, виконано повний імпорт
> на сервері й виправлено згадані проблеми обробки URL та часткового імпорту.
> Поточна реалізація зберігає cookies на сервері у приватному файлі; це відрізняється
> від початкового варіанта плану з передаванням лише authkey. Актуальні інструкції,
> обмеження та опис безпеки — у [README](../README.md).

Досліджено 2026-10-24. Акаунт користувача мультиплатформений; вхід через браузер доступний.
Дослідження доповнено успішною перевіркою на акаунті користувача через LibreWolf.
Пряме перехоплення PS5 не проводилося.

## Висновок

Перевірений шлях — отримати `authkey` через авторизований HoYoverse-акаунт,
без встановлення Genshin на ПК та без перехоплення мережі PS5.
У genshin.py є реалізований `fetch_authkey()` для global/overseas акаунтів.
Реальна доступність підтверджена для європейського UID користувача.

## Результат практичної перевірки

- У профілі LibreWolf знайдені три потрібні cookies для `.hoyoverse.com`.
- `getUserGameRolesOfRegionByCookieToken` повернув персонажа на `os_euro`, AR 60, `retcode=0`.
- `genAuthKeyByCookieToken` повернув authkey з `auth_appid=webview_gacha`, `retcode=0`.
- Окремим HTTP-клієнтом, без cookies акаунта, викликано актуальний `getGachaLog`.
  Прочитано п'ять останніх круток персонажного банера (`301`), `retcode=0`.
  Час цих записів — `2026-10-21 16:38:12` за відповіддю API.
- Значення cookies та authkey не друкувалися та не зберігалися у проєкт.
  Тимчасова копія зайнятої браузером SQLite-бази видалена після читання.
- Увесь імпорт у SELFwishes ще не виконувався; візуальне звірення з PS5 залишається
  окремою перевіркою користувача. Одержання ключа й читання реальної історії підтверджено.

Практичний експеримент виконувався прямими HTTP-запитами через `httpx`.
У встановленому локально `genshin` версії 1.0.0 немає `fetch_authkey()`;
від цієї старої бібліотеки перевірений спосіб не залежить.

Пряме отримання URL із браузера Genshin на звичайній PS5 залишається
непідтвердженим: проксі підтримується, але для HTTPS потрібна довіра клієнта
до сертифіката перехоплювача. Підтвердженого способу налаштувати цю довіру
саме у PS5 Genshin WebView не знайдено.

## Як працює SELFwishes

- `frontend/src/components/ImportModal.vue`: приймає URL; paimon.moe — посилання на інструкцію.
- `backend/app/routers/import_wishes.py`: дістає authkey, завантажує банери, зберігає історію.
- `backend/app/services/hoyo.py`: розбирає URL та викликає `getGachaLog` з пагінацією `end_id`.
- У моделях БД немає поля для збереження authkey чи cookies.

SELFwishes вже читає HoYoverse напряму. Прив'язки імпорту до ПК немає;
поточна інструкція отримання URL залежить від ПК.

Перед розширенням імпорту слід виправити два місця:

1. `parse_auth_url()` бере довільні host/path із введеного URL та використовує їх
   як адресу API. Посилання на HTML-сторінку історії через це може не працювати;
   також можливі запити бекенда до сторонніх або внутрішніх адрес.
   Треба витягувати параметри, а адресу API вибирати з фіксованого списку.
2. Роут приховує всі `HoyoAPIError` для окремих банерів. Це маскує справжню
   причину невдачі та допускає частковий імпорт без повідомлення про пропуски.

Поточна адреса за замовчуванням — `hk4e-api-os.hoyoverse.com/event/gacha_info/api/getGachaLog`.
У перевіреному коді genshin.py та paimon.moe використовується
`https://public-operation-hk4e-sg.hoyoverse.com/gacha_info/api/getGachaLog` для global.
Це не доводить, що стара адреса вже перестала працювати.

## Які токени треба розрізняти

| Дані | Призначення та значення для задачі |
| --- | --- |
| Genshin UID | Ідентифікатор персонажа/сервера; сам по собі не авторизує історію круток. |
| `authkey` з `auth_appid=webview_gacha` | Тимчасовий доступ до історії круток. Саме його потребує імпортер. |
| `authkey` з `auth_appid=csc` | Інший контекст: журнали транзакцій. Не слід підміняти ним ключ історії. |
| `ltoken`, `ltoken_v2` | Cookies авторизації для інших HoYoLAB API; це не готовий authkey історії. |
| `cookie_token_v2` + `account_mid_v2` + `account_id_v2` | Cookies, які вимагає перевірений `fetch_authkey()`. Значно ширші облікові дані, ніж ключ історії. |
| `stoken` | Окремий токен сесії; у різних інструментах є обміни між типами токенів. Для обраного overseas-механізму окремо отримувати stoken не потрібно. |

Документація genshin.py описує authkey як read-only із терміном близько 24 годин.
Практично треба обробляти протермінування, а не покладатися на точний час.
Ключ відкриває приватну історію; cookies акаунта не можна прирівнювати до цього ключа.
Ключ із довільного web event, QR чи Feedback не обов'язково має потрібний контекст.
На актуальній сторінці paimon.moe прямо зазначено, що старий Feedback-спосіб більше не працює.

## Кандидат без перехоплення PS5

Перевірений код `genshin.py` виконує:

```text
POST https://api-account-os.hoyoverse.com/binding/api/genAuthKeyByCookieToken

game_uid: <Genshin UID>
region: <os_euro / os_usa / os_asia / os_cht>
game_biz: hk4e_global
auth_appid: webview_gacha
```

Авторизація — cookies акаунта. Повернений authkey використовується для `getGachaLog`.
Функція має обмеження OVERSEAS; для китайських акаунтів цей висновок не переноситься автоматично.
У релізі genshin.py 1.7.31 є відповідна зміна `d739717`.

План перевірки:

1. На власному комп'ютері локально отримати потрібні cookies з авторизованої
   сесії HoYoverse. Наявність звичайного входу не гарантує, що всі три cookies
   вже присутні саме на відкритому домені; перевірити їхні назви без публікації значень.
2. Локальним клієнтом genshin.py викликати `fetch_authkey(uid=...)`
   для конкретного UID, щоб уникнути вибору іншого сервера.
3. Отримати одну сторінку історії та звірити її з історією на PS5.
4. Якщо це працює, підключити результат до SELFwishes:
   локальний помічник передає лише authkey/URL; cookies залишаються на комп'ютері.
5. Не записувати cookies, authkey або повні URL з ключами у логи, git чи аналітику.

Успіх — правильний UID і збіг круток, а не лише успішне отримання ключа.
Кроки отримання ключа та читання сторінки вже виконані успішно для цього акаунта.
Звірення з екраном PS5 і інтеграція локального помічника залишаються наступними кроками.

## Що дає перехоплення PS5

| Варіант | Оцінка |
| --- | --- |
| Wireshark / tcpdump на роутері | Для HTTPS не показує шлях і query з authkey; корисний для діагностики з'єднань. |
| HTTP CONNECT proxy | Сам по собі тунелює TLS, не відкриває authkey. |
| mitmproxy з дешифруванням | Потрібна довіра WebView до CA проксі; можливі додаткові перевірки сертифікатів. Для PS5 Genshin не підтверджено. |
| DNS-підміна | Не усуває перевірку сертифіката та не розшифровує HTTPS. |
| QR вебподії / Feedback | Немає підтвердження, що актуальний URL дасть authkey для `webview_gacha`. |
| Той самий акаунт на ПК/мобільному клієнті | Альтернатива з доступного клієнта; потребує встановлення та запуску гри. |

Якщо окремо досліджувати прямий шлях, перший експеримент — перевірити,
чи WebView історії взагалі використовує системний proxy PS5. Тунелювання
можна перевіряти без дешифрування. Це ще не доказ можливості отримати токен.
